# 入库规范 · R5（文枢 references/）

> **定位**：文献怎么进知识库、怎么保证质量。定义文枢的"文献导入流水线"与质量门。
> **底稿来源**：文枢知识库实战入库流水线（unified_import.py 1006 行）+ jasminum（Zotero 中文元数据补全参考）
> **实现说明**：unified_import.py 为文枢知识库（个人库）实战体系；本 skill 的 scripts/ 提供精简实现——PDF 提取（pdf_extract.py）、目录解析（toc_parse.py）、偏移检测（offset_detect.py）、分篇切分（split_works.py）、知识库生成（kb_builder.py）、锚点注入（anchor_injector.py）、质量门（quality_gate.py）、EPUB 拆篇（epub_split.py）、DOCX 提取（docx_extract.py）、知识库巡检（kb_health.py / snapshot_diff.py）、反链回填（cited_by_backfill.py）、链接注入（link_inject.py）。TXT 由 agent 直接读取。
> **通用化原则**：流水线骨架通用，文件处理适配具体格式；Zotero 补全作为可选的元数据增强通道。
> **AI 可对接**：本规范可直接被 agent 读取执行，指导批量入库。

---

## 1. 入库流水线（主流程）

```
新资料（PDF/EPUB/DOCX/TXT）放入"待入库"区
  → ① 类型判断
  → ② 内容提取（按类型）
  → ③ 自动分类（按规则/目录）
  → ④ YAML 元数据生成
  → ⑤ L0 链接注入（post_import_hook，参考设计未内置；实际走 link_inject.py）
  → ⑥ 归档至"已入库"
```

对应实现（scripts/ 脚本，unified_import 为个人库参考）：

| 步骤 | 函数 | 职责 |
|---|---|---|
| ① 类型判断 | `pdf_extract.py` / `docx_extract.py` | 按文件/文本特征分类 |
| ② 内容提取 | `pdf_extract.py` / `epub_split.py` / `docx_extract.py` | 全文提取 |
| ③ 自动分类 | 按规则映射到子库目录 | 分类到对应子库目录 |
| ④ YAML 生成 | 入库脚本生成字段 | 生成字段（见 R1） |
| ⑤ 链接注入 | `link_inject.py`（L1 关键词） | 注入 `related_classics_extra` |
| ⑥ 归档 | agent 移动 | 移动至"已入库" |

## 2. 文件类型处理

| 类型 | 处理方式 | 说明 |
|---|---|---|
| PDF（文字层） | `scripts/pdf_extract.py`（pypdf）全文提取 | 提取后生成 YAML |
| PDF（扫描版） | OCR 管线（个人库参考，未内置） | 标记"需OCR"，由 agent 提示外部处理（见 §3） |
| EPUB | `scripts/epub_split.py`（ebooklib）拆篇 | 拆篇 + 完整 YAML |
| DOCX | `scripts/docx_extract.py`（python-docx）提取 | 提取正文 + 基础元数据 |
| TXT | 直接复制 | 自动分类 + YAML |

## 5. 链接注入（L0 目录种子）

> **实现**：scripts/link_inject.py（关键词映射表驱动，--map 传入映射 JSON）。本节 post_import_hook 为目录映射注入逻辑（L0），link_inject 按关键词匹配注入 related_classics_extra。

`post_import_hook` 逻辑（目录映射注入）：
1. 取新文件所在子目录相对路径
2. 在"子目录→经典/政策映射表"中匹配
3. 匹配成功则向 YAML 注入 `related_classics` / `related_policy` 链接

映射表示例（领域适配时替换）：

| 子目录 | 关联经典（related_classics） | 关联政策（related_policy） |
|---|---|---|
| 01_基础理论研究 | 源头文献相关卷 | — |
| 02_文化研究 | 相关原著 | 文化相关政策 |
| 03_学科前沿 | 相关原著 | 对应学科政策 |

## 6. 质量门（入库校验）

| 检查 | 脚本/方式 | 作用 |
|---|---|---|
| YAML 健康巡检 | `kb_health.py yaml` | YAML 闭合、tags 数组格式 |
| 死链检测 | `kb_health.py links` | wikilink 目标存在性 |
| 标签合规 | `kb_health.py tags --forbidden` | 禁用缩写扫描（表由调用方传入） |
| 快照与差异 | `snapshot_diff.py` | 日快照 + 变化检测（--log 写变更日志） |
| 变更日志 | `snapshot_diff.py --log` | 快照差异写入变更日志 |

**质量门规则**：
- 入库后必须通过 YAML 巡检 + 死链检测 + 标签合规
- 变更日志统一记录（脚本/AI/快照三类）
- 每日快照 + 差异检测，异常发现即报告

## 7. 操作纪律

1. **先 dry-run**：所有批量写入脚本先 `--dry-run` 预览
2. **冒烟测试**：新脚本先在小子集验证，再扩展全库
3. **批后报告**：每次批量操作生成 `{action}_report_{date}.md`
4. **不跳上游**：构建流水线按顺序执行，不跳过上游直接跑下游
5. **增量维护**：新资料走"待入库 → 处理 → 归档"流程，不直接写库
