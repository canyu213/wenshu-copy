# 入库规范 · R5（文枢 references/）

> **定位**：文献怎么进知识库、怎么保证质量。定义文枢的"文献导入流水线"与质量门。
> **底稿来源**：文枢知识库实战入库流水线（unified_import.py 1006 行）+ jasminum（Zotero 中文元数据补全参考）
> **通用化原则**：流水线骨架通用，文件处理适配具体格式；Zotero 补全作为可选的元数据增强通道。
> **AI 可对接**：本规范可直接被 agent 读取执行，指导批量入库。

---

## 1. 入库流水线（主流程）

```
新资料（PDF/EPUB/DOCX/TXT）放入"待入库"区
  → ① 类型判断
  → ② 内容提取（按类型）
  → ③ 自动分类（按规则/目录）
  → ④ YAML 元数据生成
  → ⑤ L0 链接注入（post_import_hook）
  → ⑥ 归档至"已入库"
```

对应实现（`unified_import.py` 函数结构）：

| 步骤 | 函数 | 职责 |
|---|---|---|
| ① 类型判断 | `classify_pdf` / `classify_docx` | 按文件/文本特征分类 |
| ② 内容提取 | `extract_pdf_text` / `process_epub` / `process_docx` / `process_txt` | 全文提取 |
| ③ 自动分类 | `classify_pdf` / `classify_docx` | 分类到对应子库目录 |
| ④ YAML 生成 | `parse_metadata` / `extract_docx_metadata` | 生成字段（见 R1） |
| ⑤ 链接注入 | `post_import_hook` | 按目录映射注入 `related_*`（L0） |
| ⑥ 归档 | `archive_processed` | 移动至"已入库" |

## 2. 文件类型处理

| 类型 | 处理方式 | 说明 |
|---|---|---|
| PDF（文字层） | MarkItDown 全文提取 | 提取后生成 YAML + MOC |
| PDF（扫描版） | OCR 管线 | 标记"需OCR"，分批处理（见 §3） |
| EPUB | ebooklib 拆篇 | 拆篇 + 完整 YAML + MOC |
| DOCX | python-docx 提取 | 自动分类入库 |
| TXT | 直接复制 | 自动分类 + YAML |

---

## 3. OCR 管线（扫描版）

| 项 | 说明 |
|---|---|
| 工具 | EasyOCR（CPU 模式） |
| 分批策略 | 第 1 批 ≤250 页，第 2 批 251-400 页，第 3 批 >400 页 |
| 断点续传 | checkpoint.db 支持断点续处理 |
| 性能 | 单页约 4 秒（CPU） |

## 5. 链接注入（L0 目录种子）

`post_import_hook` 逻辑：
1. 取新文件所在子目录相对路径
2. 在"子目录→经典/政策映射表"中匹配
3. 匹配成功则向 YAML 注入 `related_classics` / `related_policy` 链接

映射表示例（领域适配时替换）：

| 子目录 | 关联经典（related_classics） | 关联政策（related_policy） |
|---|---|---|
| 01_基础理论研究 | 源头文献相关卷 | — |
| 02_文化研究 | 相关原著 | 文化相关政策 |
| 03_学科前沿 | 相关原著 | 对应学科政策 |

## 6. 质量门（入库校验）

| 检查 | 脚本/方式 | 作用 |
|---|---|---|
| YAML 健康巡检 | `check_yaml_health.py` | YAML 闭合、tags 格式、字段规范 |
| 死链检测 | `check_dead_links.py` | wikilink 目标存在性 |
| 标签合规 | `check_tags.py` | 禁用缩写扫描 |
| 快照与差异 | `snapshot_diff.py` | 日快照 + 变化检测 |
| 变更日志 | `log_utils.py` | 三类变更源统一写入 |

**质量门规则**：
- 入库后必须通过 YAML 巡检 + 死链检测 + 标签合规
- 变更日志统一记录（脚本/AI/快照三类）
- 每日快照 + 差异检测，异常发现即报告

---

## 7. 操作纪律

1. **先 dry-run**：所有批量写入脚本先 `--dry-run` 预览
2. **冒烟测试**：新脚本先在小子集验证，再扩展全库
3. **批后报告**：每次批量操作生成 `{action}_report_{date}.md`
4. **不跳上游**：构建流水线按顺序执行，不跳过上游直接跑下游
5. **增量维护**：新资料走"待入库 → 处理 → 归档"流程，不直接写库

---

## 8. 领域适配说明

- 文件类型处理适配领域文献格式（如法学 PDF、历史档案）
- L0 映射表按领域"子目录→源头/政策"重新配置
- Zotero 补全通道可选启用（文枢兼容 Zotero 生态）
