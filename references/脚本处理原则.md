# 脚本处理原则｜ChatGPT 适配

本文件记录原版 Wenshu Python 工具真正需要继承的**确定性行为**。ChatGPT 原生处理可以替代实现手段，但不得悄悄降低这些质量边界。

## 总原则

1. **阶段化中间产物**：大文档处理分阶段，每阶段都有可检查的输出，不把提取、切分、建库混成一次模型生成。
2. **fail-fast**：上游质量门失败就停止依赖它的下游步骤。
3. **默认不破坏原始数据**：批量修改先预览/dry-run；锚点优先输出新文件。
4. **语义与机械操作分离**：模型负责消歧、核验、关系判断；脚本负责编号、格式化、批量扫描、重复性校验。
5. **可复现**：抽样、排序、ID 和格式化尽量确定性，不依赖随机输出。

## PDF 整书流水线

### S1 `pdf_extract.py`
逐页提取为 `page_XXXX.txt` 并生成统计报告。原实现的默认哨兵：空页率 >10% 或乱码页率 >5% 即失败。ChatGPT 原生读取整本 PDF 时，也应先判断是否存在大量空页/扫描页/乱码；不能在文本明显不完整时继续声称“全量入库”。

### S2 `toc_parse.py`
目录识别使用双通道：
- A：目录页，提供篇名、书内页码范围、卷归属。
- B：正文标题页，校正真实标题和实际起始页。

正文标题是重要校验源，目录不是唯一权威。保留对范围页码、单页码、罗马数字、OCR 空格、跨行标题、重复页眉和 OCR 变体的容错；模糊匹配无法可靠消歧时必须标记人工确认。

### S3 `offset_detect.py`
按卷计算 `PDF页 - 书内页` 的偏移，取众数并报告一致性。原实现要求偏移位于 `[0,50]`；样本不少于 5 时，一致性低于 70% 失败。不要假设整本多卷书只有一个页码偏移。

### S4 `split_works.py`
优先使用正文识别得到的 `pdf_start`；结束页由显式书内结束页和“下一篇起始页 - 1”共同约束，取不造成重叠的边界。清理跨页高频页眉和孤立页码。任何范围缺失、越界、重叠或空篇都视为阻断问题。

### S5 `kb_builder.py`
每篇生成独立 Markdown。已知字段写确定值；未知 `year`、`edition` 等写 `[待补]`，不推测。PDF 锚点采用页语义，如 `^v01p0025`；EPUB 使用相同结构时必须声明 `anchor_semantics: paragraph`，避免把段号冒充页码。

### S6 `quality_gate.py`
检查文件数、锚点数、空篇、YAML title、锚点格式、卷目录与锚点卷号、`pages` 与首尾锚点一致性。人工验收采用按卷分层、等间隔的确定性抽样，默认约 10%，以便复现。

## 段落锚点 `anchor_injector.py`

- 按 `。！？；` 等句边界切分，再向目标长度合并；原默认目标约 90 字。
- Block ID 固定位数、连续、唯一，并保持单文件前缀隔离。
- 跳过并保留 YAML frontmatter。
- 生成后冻结，不因为后续模型改写随意重排既有 ID。
- 默认生成新文件或 dry-run；批量前先预览。

## 引文格式化 `format_reference.py`

严格执行“**先核验，后排版**”。模型/网页负责确认题名、作者、年份、刊物、卷期页、DOI 等；只有核验后的标准化元数据进入确定性排版。`not_found` 与 `ambiguous` 是合法结果，不能为了输出格式完整而补造字段。作者超过 3 人时按规则使用“等/et al”；中文和西文作者名称规则分开处理。

## DOCX 与 EPUB

`docx_extract.py` 只做正文和基础元数据提取：首行标题、日期模式、公文号模式。不要把正则提取升级成未经核验的语义事实。

`epub_split.py` 以章节为篇、自然段为锚点空间；优先 TOC，失败时退化为文档标题候选，再失败才整本作为一篇。默认清理简单 `[n]` 脚注标记，标题已作为元数据时从正文首段剔除。

## 知识库维护

### `link_inject.py`
只根据显式关键词映射表匹配 `title / keywords / abstract / core_viewpoint`。短且易误配的词可限制为标题+关键词。写入 `related_classics_extra` 时合并去重，不覆盖人工维护的 `related_classics`。默认 dry-run。

### `cited_by_backfill.py`
`cited_by` 是从 `related_classics` / `related_classics_extra` 反向计算出的派生索引，不手工维护。先构建反向索引、去重、预览，再写入；允许限制可写目标目录。

### `kb_health.py`
机械巡检至少包括 YAML 闭合、tags 数组格式、禁用缩写标签和 wikilink 死链。发现问题应列出来源文件和目标，不直接“智能修复”无法确定的链接。

### `snapshot_diff.py`
快照记录 Markdown 文件的路径、mtime、size、status；比较新增、删除、变化。快照与构建目录不参与自身扫描，避免递归噪声。

## 检索与图谱

`skill_rag.py` 的核心思想可保留，但在 ChatGPT 中不作为默认前置条件：
- 锚点块是检索单元；超长块按句边界拆到约 900 字量级。
- 向量只负责召回，回答仍需回到锚点内容。
- 图谱实体限制为可在文献中找到的概念/著作/人物/理论；关系限制为 source/develop/debate，并要求 evidence。
- 实体名称归一化、去自环；断点续跑和失败记录属于高级索引路径。

普通 ChatGPT 文献问答优先使用原生文件检索。只有用户明确需要长期可重复的独立向量索引、离线知识库或自托管检索时，才启用 `skill_rag.py` / `kb_index.py` 类外部索引路径。
