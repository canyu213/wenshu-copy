# 元数据方案 · R1（文枢 references/）

> **定位**：文枢知识处理的通用元数据字段设计。任何领域知识库（人文社科各学科）采用同一套核心字段，学科专属字段作为可选扩展。
> **底稿来源**：文枢知识库实战验证的字段体系（本文做通用化提炼）
> **通用化原则**：核心字段剥离学科属性；学科专属字段标注"可选扩展"；字段命名遵循"双向索引"设计。
> **AI 可对接**：本方案可直接被 agent 读取执行，字段定义即约束。

---

## 1. 核心字段表（通用，全库适用）

| 字段 | 格式 | 说明 | 维护方 |
|---|---|---|---|
| `title` | 字符串 | 条目标题（建议与文件名一致） | AI/人工 |
| `tags` | 数组 `["标签1","标签2"]` | 标签体系（见 R2 知识组织规范） | AI/人工 |
| `publish_date` | `YYYY-MM-DD` 或 `YYYY` | 发布日期/写作日期 | AI 提取 |
| `core_viewpoint` | 字符串（100 字内） | 一句话核心观点摘要 | AI 提炼 |
| `status` | 枚举 | 内容提取状态（见 §4） | AI 标记 |
| `reading_status` | 枚举 | 阅读进度（见 §4） | 人工 |
| `related_classics` | 数组 `["[[文件#^blockID]]"]` | 经典原著/原始文献引用（入链） | AI 注入 |
| `related_policy` | 数组 `["[[文件]]"]` | 政策/制度文件关联（入链） | AI 注入 |
| `related_concepts` | 数组 `["[[文件]]"]` | 概念/词条关联（入链） | AI 注入 |
| `cited_by` | 数组 | 反向索引（谁引用了本条） | **脚本自动维护，AI 禁止手改** |

**字段设计要点**：
- 入链（`related_*`）表达"本条引用了什么"——引用方向
- 反链（`cited_by`）表达"本条被谁引用"——被引方向
- 双向索引保证"从任何条目都能回溯/前向追踪"，是知识关联的基础

---

## 2. 类型专属字段（可选扩展，按领域库类型启用）

### 2.1 文献/原著类
| 字段 | 格式 | 说明 |
|---|---|---|
| `volume` | 字符串 | 卷号 |
| `edition` | 字符串 | 版本项（如"2009 版"） |
| `publisher` | 字符串 | 出版者 |
| `source_info` | 字符串 | 来源说明（如"全集/选集 第X卷"） |

### 2.2 学术论文类
| 字段 | 格式 | 说明 |
|---|---|---|
| `authors` | 数组 | 作者列表 |
| `journal` | 字符串 | 期刊名（可标注级别） |
| `keywords` | 数组 | 关键词 |
| `abstract` | 字符串 | 摘要（可选） |
| `rating` | `★★★/★★☆/★☆☆` | 论文评级（可选） |
| `quality_check` | 枚举 | `has_definition / has_logic / has_argument / has_contribution`（质量检查） |
| `pdf_path` | 字符串 | 原文文件路径 |

### 2.3 政策/制度文件类
| 字段 | 格式 | 说明 |
|---|---|---|
| `publisher` | 字符串 | 发布主体 |
| `doc_number` | 字符串 | 文号 |
| `topic` | 字符串 | 主题分类 |
| `source_url` | 字符串 | 来源链接 |

### 2.4 词条/概念类
| 字段 | 格式 | 说明 |
|---|---|---|
| `definition` | 字符串 | 定义 |
| `synonyms` | 数组 | 同义词/别名 |

---

## 3. 引用格式规范

引用其他条目时必须携带锚点与页码信息：

```markdown
> 引文内容……
> ——《著作名》，第X卷，第Y页
> [[文件名#^blockID]]
```

- 无页码时标注 `[页码待查]`，**禁止编造页码**
- 锚点规范见 R3 段落锚点规范

---

## 4. 状态枚举

| 字段 | 取值 | 含义 |
|---|---|---|
| `status` | `全文已提取` | 源文本已完整提取到正文 ✅ 最常见 |
| | `需OCR` | 扫描版无文字层，待 OCR |
| | `待补全` | 仅有元数据框架，需补全文 |
| `reading_status` | `待读` | 已入库未阅读 |
| | `精读` | 已深度阅读、有批注 |

---

## 5. 字段规范细则

1. **核心范畴不得缩写**：`思想政治教育` 不写 `思政`；`中国式现代化` 不写 `中式现代化`；任意简写 → 全称
2. **加法不替换**：新增字段叠加在已有字段之上，不删除既有内容
3. **AI 可对接**：所有字段定义明确，agent 可直接读取执行；违反字段定义的回答视为无效
4. **同一份元数据是唯一事实源**：不从多份文件复制同一字段值（对齐 ppt-master 的"单一事实源"原则）

---

## 6. 操作禁忌（AI 必须遵守）

- ❌ 严禁批量修改已有文件的 YAML 字段
- ❌ 严禁编造不存在的文献/字段值
- ❌ 严禁给未核实内容补 `core_viewpoint`
- ❌ 严禁修改 `cited_by` 字段（脚本自动维护）
- ❌ 严禁删除已有标签或字段

---

## 7. 领域适配说明

本方案为**通用版**。各学科领域库启用时：
1. 核心字段表（§1）全量启用，不修改
2. 类型专属字段（§2）按领域需要启用对应类型
3. 标签 C 组（学科领域）按学科替换——见 R2 知识组织规范
4. 引用习惯（如某学科引文格式差异）——见 R4 引文规范

> 实例：文枢知识库的字段体系即本方案的"已启用版"（详见《重建指南》§3.3 对照）。
