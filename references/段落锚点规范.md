# 段落锚点规范 · R3（文枢 references/）

> **定位**：段落级精准引用的实现规范——全库每个语义段落拥有唯一锚点（Block ID），支持 `[[文件#^blockID]]` 精准引用与溯源。
> **底稿来源**：马克思主义知识库《重建指南》§4.3 + 《AI 对接指南》§2 + 《00_总导航》Block ID 速查（65 万+ 锚点实战验证）
> **通用化原则**：8 套命名空间提炼为通用规则——每子库一套前缀，前缀含库标识 + 卷/篇 + 段落位。
> **AI 可对接**：本规范可直接被 agent 读取执行，指导锚点生成与引用。

---

## 1. Block ID 设计原则

| 原则 | 说明 |
|---|---|
| **前缀隔离** | 每子库一套独立前缀，命名空间严格隔离，杜绝冲突 |
| **格式统一** | 同一子库内格式一致（前缀 + 卷/篇 + 段落位） |
| **段落位固定位数** | 用固定位数（如 4 位）保证字典序 = 阅读序 |
| **机器可生成** | 锚点由脚本批量生成/注入，AI 不手改 |
| **唯一且稳定** | 锚点生成后不再变更（避免引用失效） |

---

## 2. 命名规范

### 2.1 通用结构

```
^<前缀><卷/篇标识><p><段落位>
```

| 部分 | 规则 |
|---|---|
| 前缀 | 每个子库唯一（如 `^v`、`^d`、`^l_xj`） |
| 卷/篇标识 | 卷号 / 章号 / 篇号（用 2 位数字） |
| `p` | 段落标记（分隔符） |
| 段落位 | 4 位数字（`0001` 起） |

### 2.2 前缀命名建议

| 库 | 前缀 | 格式示例 |
|---|---|---|
| 源头文献-卷本 | `^v` | `^v23p0052` |
| 源头文献-文集 | `^mj_w` | `^mj_w01p0005` |
| 理论演进-选集 | `^l_xj` | `^l_xj1p0005` |
| 政策决议 | `^r` | `^r3-004` |
| 当代理论-篇目 | `^d` | `^d3-ch01-p0008` |
| 哲学笔记-专题 | `^l55-topic` | `^l55-topic-dialectics-p0006` |

> ⚠️ 注意分隔符一致性：同一库内格式必须严格统一（如 `^l18-ch01p0003` 的 ch 与 p 之间无 `-`，`^r3-003` 的节与段之间有 `-`）——规则写死后不许混用。

### 2.3 段落切分粒度

- **按语义段落**切分：标题、段落、表格独立成锚
- 长段落不强行切分；短内容（如列表项）可合并为同一段落锚
- 锚点对应"引用单位"——引用到最小可引用的语义单元

---

## 3. 引用格式

### 3.1 标准引用

```markdown
> 引文内容……
> ——《著作名》，第X卷，第Y页
> [[文件名#^blockID]]
```

### 3.2 无页码兜底

```markdown
> 引文内容……
> [[文件名#^blockID]]
> [页码待查]
```

### 3.3 引用规则

1. **必须携带锚点**：引用他人内容必须带 `[[文件#^blockID]]`
2. **禁止编造页码**：无页码标 `[页码待查]`，不猜
3. **锚点必须真实存在**：引用前确认目标文件与锚点存在（死链检测）
4. **正文可全文引用**：研究文献全文已提取时，可直接引用正文段落

---

## 4. 批量注入与维护

| 场景 | 方式 |
|---|---|
| 初始锚点生成 | 脚本按段落切分规则批量注入 |
| 新内容入库 | 入库流水线自动生成（见 R5） |
| 锚点校验 | 死链检测脚本扫描 `[[文件#^blockID]]` 目标存在性 |
| 变更管理 | 锚点生成后冻结，不随正文修改重排 |

---

## 5. 操作纪律

1. 锚点生成用脚本，不手写
2. 不批量修改已有文件的锚点
3. 引用前校验锚点存在性
4. 锚点命名规则一旦确定，不混用格式

---

## 6. 领域适配说明

各学科领域库启用时：
1. 按 §2 为每个子库分配前缀（库标识用领域缩写）
2. 段落切分粒度按文献类型调整（如论文按段落、辞典按词条）
3. 引用格式统一遵循 §3

> 实例：马克思主义知识库 65 万+ Block ID（8 套命名空间）即本规范的"已启用版"（详见《AI 对接指南》§2）。
