## 一、问题：引文为什么需要"可溯源"

学术写作的底线是引文不编造。通用 AI 工具在这一点上不可靠：回答流畅，出处缺失，或出处漂移。引文指向的段落与论点无关，是检索增强类工具最常见的失败方式。

人文研究者面对的现实更具体。一篇论文的引文要过两关：一是页码核对，引文对应的段落要真的在那一页；二是格式合规，不同期刊的著录规则各有差异。两件事靠人工完成，成本高，且发生在写作的最后阶段。论点已成，核对变成补救。

文枢把出处做成数据结构的一部分。引文从生成起就携带锚点，锚点指向原文段落。核对不再是写作后的补救，而是回答的一部分。

## 二、方案：段落级锚点

### （一）为什么锚点设在段落级

锚点粒度决定溯源的精度。整篇文献一个锚点，定位不到具体段落。句子级锚点过碎，脱离上下文，引用时还要拼回语境。段落是语义单元，也是最小可引用的单位。

切分规则按语义执行：标题、段落、表格独立成锚；长段落不强行切分；短内容可合并。锚点对应"引用单位"，不是物理行。

### （二）锚点设计的三条原则

一是命名空间隔离。每个子库一套独立前缀，格式如 `^v23p0052`。马克思主义知识库运行 8 套命名空间，累计 65 万以上锚点，无冲突。

二是固定位数。段落位用 4 位数字，字典序等于阅读序，机器可排序、可校验。

三是生成后冻结。锚点由脚本批量注入，生成后不随正文修改重排。引用不会因版本变动失效。

### （三）多卷本的页码难题

毛选实证暴露了一个通用问题：多卷本各卷页码独立编号。全书偏移恒定的假设只对单卷本成立。毛选四卷的实际偏移是 9、22、30、41，逐卷不同。

锚点因此带卷号：`^v{卷2位}p{页码4位}`。入库流水线做分段偏移检测，每卷独立校准。这一能力可直接迁移到其他多卷本文献库。

## 三、溯源链路：从回答到原文

检索问答的输出逐点携带锚点。格式如 `[[第一卷\实践论.md#^v01p0288]]`。从回答到原文是两步：锚点定位文件，块 ID 定位段落。

实证记录（2026-08-19 重跑 5 问）：回答每点均带锚点，可点回原文核对。Q1 与 8/17 示例回答逐点一致，锚点相同。同一问题不同时间回答，出处稳定。

## 四、引文引擎：核验与排版分离

### （一）为什么分离

排版是确定性工作：元数据齐备时，国标格式由规则决定，脚本可以精确完成。核验是不确定性工作：文献信息缺失、冲突、存疑时，需要判断。两者混在一起，核验会被排版跳过，排版会被核验拖慢。

文枢采用两阶段架构。核验阶段由 agent 调用 API 模型检索公开元数据，比对题名、作者、年份、载体。排版阶段由确定性脚本把核验通过的元数据渲染为国标引文。

### （二）核验的诚实原则

引文工具的核心能力，是知道什么时候不能确定。四条纪律：

1. 不凭题名猜测文献信息，查不到就输出"未找到"
2. 无页码标注"页码待查"，不猜
3. 多来源冲突且无法判定权威时，明确报歧义，不替用户选
4. 聚合站结果不当作权威来源

### （三）GB/T 7714-2025

引文引擎以 GB/T 7714-2025 为规则基准，兼容 2015 版输出。新国标的主要变化：新增预印本类型、著录类型细化、引入全角标点规范。

库内引用与投稿引用双轨。库内引用用锚点制：引文内容、出处、`[[文件#^blockID]]` 三件套。投稿引用用数值制：正文标注序号，文末按序排列文献表。

## 六、边界

锚点保证"可回原文核对"，不保证"核对结论正确"。两点说明：

一是锚点正确性依赖入库质量。OCR 残留、页码偏移异常会传导到锚点。毛选库的 4 类可接受项见实证报告。

二是生成侧可能出错。5 问重跑中，Q1 补充说明段出现 1 处锚点卷号错标（第三卷文件标注 v01 锚点）。核心回答锚点全部正确，瑕疵已标注。

溯源的最终判断权在研究者的核对，不在工具。

## 七、结论

可溯源的本质，是把出处从写作时的记忆，变成数据的结构。锚点让每一次引用都可回原文，核验让每一次格式化都诚实。两件事合起来，就是文枢对"引文不编造"的实现。
