# 规划：通用入库流程 v2（整本 PDF → md 知识库）

> **版本**：V2.1 | **日期**：2026-08-16
> **状态**：已确认，待实现
> **V2.1 更新**：根据毛选实测 + 流程审视，补充 6 项通用性修正（双通道目录解析/分段偏移检测/卷感知切分/元数据能力边界/人工抽查交互/S7 衔接）
> **定位**：对 `workflows/文献导入.md` 的**补充场景**——文献导入.md 覆盖"单篇/小批"入库；本流程覆盖**整本 PDF（书籍级）→ 分篇 md 知识库**。
> **背景**：以《毛泽东选集》PDF 为样本实测了第一版流程（extract → parse_toc → locate_works → gen_md），暴露私有依赖与定位误判问题。本规划为通用化改造方案。

## 一、经验教训（从毛选实测暴露）

### 1.1 私有依赖（skill 不可复用）

| 教训 | 原实现 | 问题 |
|---|---|---|
| 定位基准绑定 03 卡片 | `locate_works.py` 用 03 卡片标题做定位基准 | 别人下载 skill 无 03 卡片，无法复用 |
| 元数据抄 03 卡片 | `gen_maoxuan_md.py` 从 03 卡片抄 volume/pages/year | 同上 |
| 页码偏移硬编码 | 所有脚本写死 `+9`（书内页码 = PDF页 - 9） | 别的 PDF 偏移不同 |
| 总页数硬编码 | `ingest_maoxuan_full.py` 写死 1559 | 别的 PDF 页数不同 |

### 1.2 定位误判（算法准确性）

| 误判 | 表现 | 原因 |
|---|---|---|
| 小节误判 | "组织起来"被当独立篇（实为《湖南农民运动考察报告》小节） | 标题定位匹配到正文内小节标题 |
| OCR 错位 | "中国革命和中国共产党"定位 63 页（实际 585+ 页） | 标题 OCR 变异 + 前缀匹配过宽松 |
| 同页多篇 | 3 处两到三篇挤同页 | 相邻篇标题被匹配到同页 |

## 二、通用入库流程 v2 设计

```
输入：任意 PDF 书籍（含多卷合订本）
  S1  提取全文          逐页提取，输出 page_XXXX.txt
  S2  目录解析          双通道：目录页解析 + 正文标题扫描 → 篇目清单（含卷归属）
  S3  页码偏移检测      分段检测（按卷/章节），允许不同段不同偏移
  S4  分篇切分          按目录页码范围 + 卷感知（页码空间按卷处理）→ 每篇正文 + 页码锚点
  S5  生成 md 知识库    YAML（能力边界内提取）+ 页码锚点（带卷号）+ 页内自然段
  S6  汇总质量门        全库统计 + 人工抽样验收（结构化清单交互）
  S7  （可选）LightRAG 索引  从 md 读正文建检索索引
输出：md 知识库（主产物） + 可检索索引（辅助）
```

### 关键设计：零外部依赖

- 定位基准 = **PDF 自带目录 + 正文标题双通道**（非外部卡片）
- 页码偏移 = **分段自动检测**（S3，按卷/章节）
- 元数据 = **能力边界内提取**，缺失留空 + 标记"[待补]"
- 无任何硬编码页码/篇数/偏移

### 卷感知设计（合订本通用化）

**不"分卷执行"，而"卷感知"**——流程整体跑一次，卷作为逻辑分组贯穿 S2/S4/S5：

| 环节 | 卷感知动作 |
|---|---|
| S2 目录解析 | 识别"第一卷/第二卷…"分组标记 → 每篇目挂到所属卷 |
| S4 分篇切分 | 页码空间按卷处理：若每卷页码重置，各卷独立偏移 |
| S5 生成 md | 锚点带卷号（`^v01p0282`）、输出目录按卷分（`第一卷/`） |

> 毛选 4 卷页码连续是特例；卷感知让 v2 兼容"每卷重置页码"的普遍多卷本。

### V2.1 六项通用性修正

| # | 问题 | 修正 |
|---|---|---|
| 1 | S2 目录解析单点脆弱（毛选目录 OCR 差，仅解析 46/145） | **双通道交叉**：目录页解析 + 正文标题扫描（"页码+篇名+＊"模式），取并集，冲突标"需人工确认" |
| 2 | S3 假设偏移恒定（合订本/前言/插页偏移可不同） | **分段检测**：按卷/章节分别采样，允许不同段不同偏移 |
| 3 | 多卷本每卷页码重置未处理 | **卷感知切分**（见上） |
| 4 | S5 元数据能力边界不清 | 明确边界：必得（篇名/页码范围/卷），可得（年份，篇名带括号时），通常无（作者/出版社/edition）→ 缺失标"[待补]"不编造 |
| 5 | 人工抽查在 agent 工作流落地不清 | 抽查输出**结构化清单**（篇名/页码/置信度/疑点），agent 呈现给用户，用户确认/修正后继续 |
| 6 | S7 与 md 衔接未细化 | 读 md"## 正文"部分，按 `^v01p0282` 锚点切 chunk，doc_id 用篇名，复用 test_rerank 配置模式 |

## 三、分层质量门（本版核心设计）

### 3.1 设计原则

> **每环节自动校验（fail-fast）+ 语义环节人工抽查 + S6 汇总验收**。
> 只做 S6 末端检验 → 错误积累难定位；每环节都人工 → 成本过高。
> 分层：确定性转换（S1/S3/S5）机器校验足够；语义判断（S2/S4）必须人眼。

### 3.2 各环节校验表

| 环节 | 自动校验（内嵌 fail-fast） | 人工抽查 | 哨兵值（不过即停） |
|---|---|---|---|
| **S1 提取** | 页数 = PDF 页数；空页率；乱码率（`Ã`/`�` 字符比例） | 无 | 空页率 > 10% 或乱码率 > 5% → 停 |
| **S2 目录解析** | 篇目数 ≥ 阈值；页码范围合法（递增、无重叠） | **⚠️ 必查**：抽 5 篇对照正文标题 | 篇目数 < 5 → 停 |
| **S3 偏移检测** | 多页采样偏移一致；偏移量 ∈ [0, 50] | 无 | 偏移不一致 → 停 |
| **S4 分篇切分** | 每篇起始页有目录条目；篇间无重叠/无缺失页 | **⚠️ 抽 3-5 篇**核对首尾页 | 页区间重叠 → 停 |
| **S5 生成 md** | 文件数 = 篇目数；锚点格式合法；YAML 必有 title | 无 | 锚点格式错误 → 停 |
| **S6 汇总质量门** | 全库统计：篇数/总字数/锚点数/空篇数 | **✅ 抽 10% 通读** 最终验收 | 空篇数 > 阈值 → 打回 |

### 3.3 fail-fast 哨兵说明

每个自动校验不通过即**停止报错**，不让脏数据流向下游。错误在最源头暴露，而非积累到 S6。
