## 一、问题：人文知识的两种需求

人文研究对文献有两种需求，现有工具各解决一半。

需求一是关联。概念从哪来，思想怎么发展，谁和谁在争论。这是思想史研究的基本动作，马理论、哲学方向尤其如此。通用知识图谱软件能画图，但只显示"链接"，不区分关系类型。两个概念之间是继承还是对立，图谱不回答。

需求二是检索。问一个问题，从千篇文献中找出答案。通用检索工具只命中字面关键词，给不出上下文。通用 RAG 能回答，但回答不带出处，研究者不敢直接用。

文枢的组合方案：三类关系的谱系图谱，加轻量向量检索，加图谱增强。关联与检索互相支撑。

## 二、理论谱系：三类关系

### （一）为什么是这三类

来源、发展、争论，对应思想史研究的三个基本动作：追源、梳理、辨争。

| 关系 | 含义 | 实例 |
|---|---|---|
| 来源 source | 概念或理论源自何处 | 中国社会各阶级的分析 -[source]-> 毛泽东 |
| 发展 develop | 在既有基础上推进 | 马克思列宁主义 -[develop]-> 人民民主专政 |
| 争论 debate | 对立、回应或批评 | 亡国论 -[debate]-> 持久战 |

三类关系的选择是刻意收敛。关系类型越多，标注越泛，图谱越接近蜘蛛网。三类覆盖"思想从哪来、怎么走、与谁辩"，够用且可验证。质量门同步收紧：每条关系必须有原文锚点支撑，禁止凭印象连关系。

### （二）抽取与兜底

关系由 DeepSeek 自动抽取，每条强制附原文 evidence。红线只有一条：只从文本抽取，不造关系。

两个工程问题的处理：

一是篇目自指缺失。正文不提篇名的篇目，图谱里没有对应的文献实体。处理：以篇目名补为文献实体。补实体，不补关系，守住"只从文本抽取"红线。

二是实体未归一。"《论持久战》"与"论持久战"并存，异形实体成对出现。处理：去书名号、合并异形，48 组已固化进工具。

### （三）质量验证

毛选全量图谱：137 篇，1219 实体，1278 关系。evidence 完整率 100%。随机抽核 5 条，与原文逐字吻合。

与人工知识库的关系是互补。知识库的 `cited_by` 是"论文→著作"横向引用网络，人工构建。谱系图谱是"著作内概念→概念"纵向思想谱系，自动抽取。以实践论为例。知识库记：实践论被 4 篇论文引用。图谱记：实践论 -[debate]-> 教条主义、经验主义。横向管引用，纵向管脉络，两套网络合成完整知识图景。

## 三、轻量检索：模式 D

### （一）为什么轻量

人文个人库的规模，千篇级文献、万段级文本。毛选 137 篇、1402 个段落锚点，是典型样本。

重型向量数据库为百万级向量设计，部署要服务、要运维，超出个人研究者的承受范围。模式 D 的答案：embedding API 出向量，numpy 本地算余弦。一个 Python 脚本完成索引与检索，数据不出本机。

### （二）三层架构

检索问答由三层构成：

| 层 | 职责 | 实现 |
|---|---|---|
| 向量召回 | 语义相似度排序，取 top-6 | bge-m3 中文 embedding + numpy 余弦 |
| 图谱增强 | 实体邻接关系加权，补充间接关联 | 自研图谱存储（skill_rag.py） |
| 锚点溯源 | 回答逐点带出处 | `[[文件#^blockID]]` 段落级引用 |

### （三）图谱增强解决什么

纯向量检索有一个盲区：它按语义相似度排序，捕捉不到概念间的间接关联。问"实践论"时，只靠向量召回会漏掉与它论战的"教条主义"。

图谱增强补上这一环。检索命中的实体，其邻接关系一并进入上下文。实测 Q1：检索《实践论》，图谱联动输出论战关系。陈独秀 -[debate]-> 毛泽东，张国焘 -[debate]-> 毛泽东。回答者能看到论战的对象与阵营。

## 五、边界

一是关系抽取依赖 LLM。实体归类存在噪声。毛选库中"党的第六次全国代表大会"被标为 event，影响小，接受。

二是图谱只做辅助，不做裁判。关系是建议，结论由研究者判断。工具的价值是让研究者少做检索的重复劳动，替代不了文本的判断。

三是轻量有适用范围。本地 numpy 余弦在万级向量内高效，百万级向量需升级方案。个人知识库规模内，轻量成立。

## 六、结论

三类关系给知识以脉络，轻量检索给脉络以入口，锚点给检索以凭证。谱系图谱与检索问答互为表里，加上方法论①的溯源机制，构成文枢对人文知识处理的完整回答。
