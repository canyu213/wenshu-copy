# 工作流：文献导入（文枢 workflows/）

> **目标**：把新文献导入知识库，完成全文提取、元数据生成、链接注入与归档。
> **依赖**：R1 元数据方案 / R2 知识组织规范 / R3 段落锚点规范 / R5 入库规范
> **执行方**：文枢 agent（智能体 + API 模型），脚本负责确定性操作。

---

## 1. 输入

- PDF / EPUB / DOCX / TXT 文件（或 Zotero 导出条目）

## 2. 执行步骤

```
Step 1  接收：新文件放入"待入库"区
Step 2  类型判断：classify_pdf / classify_docx（按文件/文本特征分类）
Step 3  内容提取：
        - PDF 文字层 → MarkItDown 全文提取
        - PDF 扫描版 → 标记"需OCR"，进 OCR 管线（分批，断点续传）
        - EPUB → ebooklib 拆篇
        - DOCX → python-docx 提取
        - TXT → 直接复制
Step 4  自动分类：按规则映射到对应子库目录（R2 子库结构）
Step 5  生成 YAML 元数据：按 R1 字段规范（title/tags/publish_date/core_viewpoint/status...）
Step 6  生成段落锚点：按 R3 规范为段落注入 Block ID
Step 7  L0 链接注入：post_import_hook 按"子目录→源头/政策"映射注入 related_*（R5 §5）
Step 8  归档：处理完的文件移至"已入库"
```

## 3. 输出

- 入库的 .md 文件（含全文 + YAML + 锚点 + 链接）
- 变更日志记录（脚本/AI 统一写入）

## 4. 质量门

- [ ] YAML 健康巡检通过（字段规范、格式闭合）
- [ ] 死链检测通过（wikilink/锚点目标存在）
- [ ] 标签合规（核心范畴不缩写）
- [ ] 快照更新（日快照 + 差异检测）

## 5. 操作纪律

1. 批量写入先 `--dry-run`
2. 新脚本先冒烟测试再全量
3. 不跳上游直接跑下游
4. 批后生成 `{action}_report_{date}.md`

## 6. Zotero 通道（可选）

文献从 Zotero 导入时，用中文题录补全策略（参考 jasminum 设计，AGPL 黑盒）补全缺失元数据；中文姓名拆分/合并参考其逻辑。

## 7. 整本 PDF（书籍级）入库（v2 通用入库流程）

> **场景**：输入是一本整书 PDF（含多卷合订本），需要自动产出**按篇分目录的 md 知识库**（主产物）+ 可选 LightRAG 索引。
> **配套**：`docs/规划_通用入库流程v2_20260816.md`（V2.1）+ `docs/入库流程测试报告_毛选.md`（实测记录）
> **工具**：`scripts/` 下 7 个通用脚本（全部参数化、零外部依赖）。

```
输入：任意 PDF 书籍
  S1  pdf_extract.py    逐页提取全文（空页/乱码校验，fail-fast）
  S2  toc_parse.py      双通道目录解析：目录页解析 + 正文标题扫描 → 篇目清单（含卷归属）
  S3  offset_detect.py  分段页码偏移检测（按卷/章节，允许每卷独立页码）
  S4  split_works.py    卷感知分篇切分（每篇正文 + 页码锚点）
  S5  kb_builder.py     生成 md 知识库（YAML 能力边界 + ^v{卷}p{页码} 锚点 + 页内自然段）
  S6  quality_gate.py   汇总质量门（全库统计 + 一致性校验 + 抽样清单）
  S7  kb_index.py       （可选）LightRAG 检索索引（chunk 前缀带 [[路径#^锚点]] 溯源标记）
输出：md 知识库（主产物） + 可检索索引（辅助）
```

### 7.1 关键设计（V2.1 六项修正）

| 设计 | 说明 |
|---|---|
| 双通道目录解析 | 通道 B（正文标题页扫描）是篇名权威来源，通道 A（目录解析）只补页码范围——目录 OCR 差时单通道只有约 1/3 篇目 |
| 卷感知 | 不"分卷执行"，卷作为逻辑分组贯穿 S2/S4/S5；每卷独立偏移（毛选实测 9/22/30/41） |
| 元数据能力边界 | 必得：篇名/页码范围/卷；可能得：年份（篇名带括号时）；缺失标 `[待补]` 不编造 |
| 零外部依赖 | 定位基准 = PDF 自带目录 + 正文标题，无硬编码页码/篇数/偏移 |

### 7.2 分层质量门（本场景核心）

> 每环节自动校验（fail-fast 哨兵）+ 语义环节人工抽查 + S6 汇总验收。

| 环节 | 自动校验（不过即停） | 人工抽查 |
|---|---|---|
| S1 提取 | 页数一致；空页率 < 10%；乱码率 < 5% | 无 |
| S2 目录解析 | 篇目数 ≥ 5；页码合法 | **必查**：抽 5 篇对照正文标题 |
| S3 偏移检测 | 偏移 ∈ [0,50]；卷内一致性 | 无 |
| S4 分篇切分 | 篇间无重叠/缺失；无空篇 | **抽 3-5 篇**核对首尾页 |
| S5 生成 md | 文件数 = 篇目数；锚点格式合法；YAML 必有 title | 无 |
| S6 汇总质量门 | 全库统计 + 空篇检测 | **抽 10%**（每卷分层）最终验收 |

**人工抽查交互**：S6 输出结构化抽样清单（篇名/卷/页码范围/锚点数/疑点），agent 呈现给用户逐条确认；发现异常 → 修正清单后重跑下游。

### 7.3 已知问题与兜底（毛选实测）

| 问题 | 兜底 |
|---|---|
| OCR 错字（关千→关于 / 间题→问题 / 衣民→农民） | 批量替换表（质检阶段统一修），不自动猜 |
| **跨行截断篇名**（长标题书约 13%） | 质检时用权威标题清单交叉验证（"当前篇名是权威标题真前缀"）→ 补全；无权威清单则从正文标题页跨行拼接 |
| 页眉残留（"篇名 页码"行 / 孤立数字行） | S5 的 strip_header 自动清理 |
| 段落级溯源 | S7 chunk 前缀带 `[[路径#^锚点]]`；LightRAG References 直接可溯源 |

### 7.4 使用示例（毛选实测命令）

```
# S1 提取
python scripts/pdf_extract.py --input 书.pdf --output work/extracted
# S2-S6（各环节输出 JSON 中间产物，可单独验证/续跑）
python scripts/toc_parse.py --input work/extracted --output work/toc_manifest.json
python scripts/offset_detect.py --input work/toc_manifest.json --output work/offset_config.json
python scripts/split_works.py --toc work/toc_manifest.json --offset work/offset_config.json --extracted work/extracted --output work/split_works.json
python scripts/kb_builder.py --split work/split_works.json --output work/kb --tags "#领域"
python scripts/quality_gate.py --kb work/kb --json work/quality_report.json
# S7（可选，需在 lightRAG 目录下用其 venv 运行，加载 .env）
python scripts/kb_index.py --kb work/kb --output work/kb_lg [--limit N] [--query "测试问题"]
```
