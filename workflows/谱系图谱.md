# 工作流：谱系图谱（文枢 workflows/）

> **目标**：把知识库的概念/学者/理论关系组织为可检索的"谱系图谱"——按来源/发展/争论三类关系 + 时间维度，支撑理论脉络检索。
> **依赖**：R2 知识组织规范（脉络链路）/ R1 元数据方案 / R3 段落锚点规范
> **执行方**：文枢 agent（智能体 + API 模型抽取关系），skill_rag.py 自研图谱存储（LightRAG 为对照参考）。

---

## 1. 输入

- 知识库文献（源头/发展/研究/词条各层）
- 用户需求（梳理某概念/学派的谱系）

## 2. 关系类型定义

从文献中抽取三类核心关系（对应文枢"理论谱系"）：

| 关系 | 含义 | 示例 |
|---|---|---|
| **来源** | B 概念/理论源自 A | 某概念来源于原著某卷 |
| **发展** | B 在 A 基础上发展 | 某思想继承并发展经典 |
| **争论** | B 与 A 对立/回应/批评 | 某学派批判另一学派 |

叠加时间维度（概念出现/发展的年份），定位命题在理论演进中的位置。

## 3. 执行步骤

```
Step 1  锚定主题：确定要梳理的概念/学者/理论（用户指定或建议）
Step 2  抽取实体：agent + API 模型从相关文献抽取实体（概念/学者/流派/文献）
        - 用 R1 字段（related_classics/related_concepts）定位已有关联
Step 3  抽取关系：按三类关系（来源/发展/争论）标注实体间关系
        - 借鉴"关系原子"方法（parent 归属 / link 连接 / contrast 对比）
Step 4  构建图谱：实体与关系写入自研图谱存储（skill_rag.py：抽取 → 实体归一化 _finalize_graph → 图谱落盘）
Step 5  叠加时间：标注关键节点时间（出版年/提出年）
Step 6  检索呈现：支持按概念检索 → 返回谱系脉络 + 原文锚点（R3）
```

## 4. 输出

- 谱系图谱（实体 + 关系 + 时间维度）
- 每个关系附原文锚点（可溯源）
- 谱系说明（agent 生成的脉络梳理，附引用）

## 5. 质量门

- [ ] 实体真实存在于库内文献（有锚点佐证）
- [ ] 关系标注正确（来源/发展/争论分类准确）
- [ ] 时间节点有出处（出版年/提出年可溯源）
- [ ] 无编造关系（抽取不到就标注"待考证"）

## 6. 操作纪律

1. 关系必须有原文锚点支撑，禁止凭印象连关系
2. 时间标注必须有出处
3. 与知识库既有关联（related_*）保持一致

## 7. 检索衔接

- 自研层抽取的谱系图谱由 `skill_rag.py` 加载：向量召回 + 图谱增强（实体邻接关系加权）+ 锚点溯源
- 检索回答带原文锚点 References（可回溯到 `文件#^blockID`）
- LightRAG 作为对照参考（kb_index.py 可选索引），不构成主链路依赖
