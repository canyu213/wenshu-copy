# 工作流：谱系图谱（ChatGPT）

## 目标
基于用户文献或可靠公开来源，组织概念、理论、学者和著作之间的来源、发展与争论关系，并让每条重要关系可回溯。

## 路径

1. 明确用户要追踪的概念/理论/学者；若已经明确，不再提问确认菜单。
2. 从当前文献、指定知识库或公共来源检索相关证据。
3. 抽取实体：concept / theory / scholar / work。
4. 只建立三类核心关系：
   - `source`：B 明确源自/继承 A。
   - `develop`：B 在 A 的基础上发展、扩展或重构。
   - `debate`：B 对 A 有明确批评、回应、争论或对立。
5. 每条关系附 evidence。只有“主题相近”不能推导出 source/develop/debate。
6. 对实体名称做归一化，去掉明显异形和自环；无法判断是否同一实体时保留为待确认，而不是强行合并。
7. 按需要叠加时间信息，但提出年/出版年必须有出处。

## ChatGPT 原生路径

对当前上传文件或连接源直接进行检索、证据提取和关系组织；聊天中使用实际文件/网页引用。需要图形化展示时，图谱数据与视觉展示分离：先形成带证据的实体-关系表，再渲染。

## 高级确定性/长期图谱路径

只有用户明确需要可重复的独立图谱文件、长期向量索引或自托管检索时，才考虑 `skill_rag.py`：锚点块作为证据单元，实体限制为概念/著作/人物/理论，关系限制为 source/develop/debate，每条关系必须带 evidence；实体归一化并去自环。

不把外部 LLM/Embedding API 当作普通谱系分析的前置条件。

## 输出

至少包含：主题范围、关键节点、关系类型、关系说明、对应证据/来源、时间信息（如有）、`待考证` 项。生成 Obsidian 产物时可附 `[[文件#^blockID]]`。
