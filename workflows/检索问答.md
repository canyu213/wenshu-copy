# 工作流：检索问答（ChatGPT）

## 目标
在用户提供或明确授权的文献集合中回答问题，回答必须能回到实际证据；普通问答不要求预先建立外部向量索引。

## 默认 ChatGPT 路径

1. 明确知识范围：当前对话文件、用户指定连接源中的文件/知识库，或用户明确要求纳入的公开资料。
2. 用当前可用的文件/连接源检索找到相关段落，不先要求用户运行 `skill_rag.py`。
3. 对命中证据做交叉核对；重要事实尽量避免只依赖一个模糊片段。
4. 回答只覆盖证据能够支持的范围。材料不足时明确说“依据有限”，并指出缺什么。
5. 聊天中使用实际文件/网页引用；若源文献已有文枢 Block ID，可同时给出 `[[文件#^blockID]]`。

## 何时启用高级索引

以下场景才考虑 `skill_rag.py` 或独立索引：

- 用户需要脱离当前 ChatGPT 会话长期复用的本地/自托管索引。
- 文献规模大到普通文件检索不适合反复全量处理。
- 用户明确要求可重复的向量召回参数、图谱文件或离线检索产物。

高级模式沿用原版原则：锚点块作为召回单元；超长块按句边界拆分；向量只负责召回；图谱关系必须带 evidence；回答最终仍回到锚点原文。

## 外部 API

DeepSeek、SiliconFlow、LightRAG、`.env` 都不是默认问答前置条件。只有用户明确选择高级外部索引方案时才说明额外依赖，并避免在聊天中索取长期密钥。

## 输出合同

回答包含：结论/解释、关键证据、证据范围限制、必要的来源引用。若不同文献存在明显冲突，分别说明各自证据，不强行合并成单一结论。
