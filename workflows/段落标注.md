# 工作流：段落标注（文枢 workflows/）

> **目标**：把知识库文献段落化——为每个语义段落生成唯一 Block ID，支持段落级精准引用与溯源。
> **依赖**：R1 元数据方案 / R3 段落锚点规范 / R5 入库规范
> **执行方**：文枢 agent（智能体 + API 模型），脚本负责批量注入。

---

## 1. 输入

- 已入库的文献 .md 文件（含全文正文）

## 2. 执行步骤

```
Step 1  段落切分：按语义段落切分正文（标题/段落/表格独立成锚）
        - 长段落不强行切分；短内容可合并
        - 锚点对应"最小可引用语义单元"
Step 2  分配 Block ID：按 R3 命名规范生成（子库前缀 + 卷/篇 + 段落位）
Step 3  批量注入：脚本按段落切分结果注入锚点
Step 4  校验：锚点唯一性 + 格式一致性（前缀隔离、段落位固定位数）
Step 5  引用就绪：段落可用 [[文件#^blockID]] 被引用
```

> **已实现工具**：`scripts/anchor_injector.py`（2026-08-16 固化，覆盖 Step 1-4）
> - 注入：`python anchor_injector.py --input 文件.md --prefix ws_gxl [--extra ch01] --output 输出.md`
> - 预览：`--dry-run`（只切分预览，不写盘，批量先跑）
> - 校验：`--check`（唯一性/前缀隔离/位数统一/连续性，失败 exit 1）
> - 纪律：只输出新文件，不改源文件（锚点生成后冻结）

## 3. 输出

- 带 Block ID 的段落化 .md 文件
- 锚点清单（供校验与统计）

## 4. 质量门

- [ ] 锚点唯一（无重复 ID）
- [ ] 前缀隔离正确（子库前缀不混用）
- [ ] 格式一致（分隔符/位数规则统一）
- [ ] 段落切分合理（无过长/过碎段落）

## 5. 操作纪律

1. 锚点生成用脚本，不手写
2. 生成后冻结，不随正文修改重排
3. 批量注入先 `--dry-run`
4. 不批量修改已有文件的锚点

## 6. 场景说明

- 入库时自动标注（与文献导入 Step 6 合并）
- 存量文献补标（对已入库无锚点文献执行本工作流）
