# 工作流：段落标注（ChatGPT）

## 目标
把文献转换为稳定的最小可引用语义单元，并生成可检查、可复用的 Block ID。

## 默认规则

1. 已有稳定锚点时先校验，不重新编号。
2. 新增锚点时优先生成新版本，不覆盖原始文件。
3. 批量任务先预览切分与 ID，再执行写入。
4. 锚点一旦被引用，默认冻结；正文修改不能成为自动重排全部 ID 的理由。

## 小规模原生路径

单篇短文或用户只需要少量锚点时，可以直接处理：

- 保留 YAML frontmatter，不把 YAML 当正文切分。
- 按语义句群形成引用单元；避免把一句话机械拆成多个碎片。
- Block ID 使用单文件独立前缀 + 固定位数序号。
- 生成后检查：唯一性、前缀一致、位数一致、序列连续。

如果用户要生成 Obsidian 知识库，正文引用形式使用 `[[文件#^blockID]]`。

## 批量确定性路径

批量 Markdown、需要稳定可复现 ID、或锚点已成为知识库引用基础时，优先使用 `anchor_injector.py` 的算法：

- 句边界：`。！？；` 等；目标长度默认约 90 字，短句合并，超长句不为满足长度强行破坏语义。
- 锚点格式：`^<prefix><extra>p<fixed-width-seq>`。
- 注入前 dry-run；注入后 check。
- 校验重复 ID、混用前缀、位数不一致、序号不连续。

脚本不可执行时，可以在小规模文本上复现这些规则；对于大批量知识库，不要声称已经达到与脚本同等的全库唯一性保证，除非实际完成了全量校验。

## 输出

返回或生成：带锚点的新 Markdown、锚点数量/命名规则、校验状态，以及任何需要人工确认的异常段落。
