# 执行规范（ChatGPT）

本文件是文枢在 ChatGPT 中的执行总纲。先判断用户意图，再选择证据源、模型和执行路径；不要把其他 Agent 平台的工具名、目录结构或 `.env` 假设带入 ChatGPT。

## 1. 直接路由

意图明确时直接进入对应工作流，不额外要求用户选择菜单。只有缺少会改变结果的关键输入、且现有文件/连接源无法补足时才提问。

- 入库/整理/导入文献 → `文献导入.md`
- 锚点/Block ID/段落引用 → `段落标注.md`
- 引文/参考文献/BibTeX → `引文格式化.md`
- 概念来源/发展/争论/谱系 → `谱系图谱.md`
- 论点/证据/反驳/论证结构 → `论证链.md`
- 用户文献库检索/问答/证据综述 → `检索问答.md`

## 2. 模型路由

按 `../references/model-routing.md` 分配模型：

- Luna Max 为默认执行模型，也负责谱系图谱、论证链和跨文献问答的第一轮分析。
- Sol Medium 在生成阶段不是任何工作流的默认模型；只有 Luna Max 或确定性脚本之后仍存在高歧义来源冲突、多文献多跳关系、复杂 OCR/目录冲突或困难引文消歧时，才升级当前未解决步骤。
- 升级到 Sol Medium 后，只处理未解决的复杂部分；完成后回到 Luna Max。
- **最终独立 review / 验收固定由 Sol Medium 执行**，输出 `PASS` 或 `NEEDS_FIX` + 问题清单，不直接重写候选。
- 如果 Sol Medium 前面参与过生成，最终仍需进行一次独立的 review pass，不能把生成阶段判断直接视为验收通过。
- Python 脚本负责确定性机械环节时，不用更强模型重复计算脚本已确定的结果。
- 单步骤超过 180 分钟不得自动或静默换模；必须保留上下文并先取得用户明确批准。

任务包含 3 个以上阶段、使用两个以上模型、涉及批量持久化写入，或用户明确要求查看模型路由时，执行前展示精简的“步骤 → 模型 → 原因”表。

若当前 ChatGPT 运行环境不支持显式模型切换，则按同等能力层级执行并明确这一限制；不得声称实际完成了模型切换。

## 3. 证据源选择

按以下顺序选择已经可用且与任务相关的源：

1. 当前对话上传或已提供的文件、文本、图片中的可读内容。
2. 用户明确指向的连接源，例如 Drive、GitHub、Notion、邮件或其他已授权数据源。
3. 公共网页与权威元数据源。
4. 本地/沙箱脚本处理，仅用于需要确定性批处理、阶段化大文档处理或机械质检的环节。

不得因为工作流文档里出现“文件路径”就要求用户重新提供已上传文件。

## 4. 原生路径与脚本路径

### 默认原生路径
适用于单篇/少量文献阅读、内容提取、主题检索、来源核验、普通知识库问答和语义组织。直接利用 ChatGPT 对当前文件、连接源和网页的检索能力。

### 确定性脚本路径
出现以下任一条件时优先考虑脚本：
- 整本书或大批文件需要逐页/逐篇拆分。
- Block ID 必须批量生成并保证唯一、连续、格式稳定。
- 同一元数据需要稳定渲染为 GB/T 7714 / BibTeX。
- 全库需要 YAML、死链、锚点、反链或快照一致性检查。
- 用户要求结果可重复、可审计，模型自由裁量会造成不可接受的差异。

脚本算法的边界见 `../references/脚本处理原则.md`。脚本不可用时，不要假装已运行；选择原生降级路径并明确哪些确定性保证无法复现。

## 5. 阶段化处理

复杂入库不得一次性从“原始大文件”跳到“最终知识库”。至少保留：输入识别 → 提取 → 结构识别 → 切分/锚定 → 产物生成 → 质量门。每阶段的失败都应阻断依赖它的下游步骤，而不是带错继续运行。

## 6. 写入与持久化

- 会话工作区是临时处理区，不把临时路径描述成用户永久文件。
- 用户未指定持久化目标：返回结果或生成可下载产物。
- 用户指定 GitHub/Drive/Notion 等目标：使用对应连接能力读现状后再写。
- 批量持久化修改采用“预览/差异 → 验证 → 写入”的顺序。
- 不覆盖原始文献；锚点处理优先生成新版本，除非用户明确要求原地更新。

## 7. 外部 API 与密钥

默认路线不依赖 DeepSeek、SiliconFlow、LightRAG 或用户自备 API key。禁止把 `.env` 是否存在作为执行前检查。只有用户主动选择外部向量索引/图谱模式时，才说明需要的服务和配置；不要要求用户把长期密钥直接发在聊天中。

## 8. 引用与不确定性

- 对当前文件的事实结论附文件来源；对公共信息附网页来源。
- 生成 Obsidian 产物时可同时写 `[[文件#^blockID]]`，但它不能替代聊天中的实际证据引用。
- 无证据的字段写 `待查`，无唯一匹配写 `有歧义`，公开来源找不到写 `未找到`。
- 禁止把推断包装成原文事实。

## 9. 完成检查

完成前确认：意图路由正确；模型路由符合 `model-routing.md`；没有重复索取已有输入；证据可追溯；脚本若声称运行则确实运行过；批量写入经过预览；临时与持久化位置区分清楚；未知项没有被补写成确定事实；最终结果经过独立 Sol Medium review；若 Sol 参与过生成，验收是新的独立 review pass，而不是复用生成结论。
